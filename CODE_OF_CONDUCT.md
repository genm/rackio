# Code of conduct

## The standard

Rackio is a small project that reviews changes strictly. That review is about
the change, never about the person who wrote it.

Everyone taking part in this repository — issues, pull requests, discussions,
reviews and security reports — is expected to:

- keep criticism attached to the code, the evidence or the decision at hand;
- accept a rejected change without treating it as a rejected person, and reject
  one without implying anything about its author;
- state disagreement plainly, including with a maintainer, and let evidence
  settle it;
- respect that contributors differ in experience, language fluency, time zone
  and the amount of time they can give.

The following are not acceptable, in any thread and regardless of technical
merit: harassment or personal attacks; sexualised language or imagery; insults
based on a person's identity or background; publishing anyone's private
information; and sustained disruption of a discussion after being asked to stop.

## Scope

This applies to every space this project controls, and to any place where
someone is representing Rackio in public.

## Reporting

Report a problem through
[GitHub's report abuse form](https://github.com/contact/report-abuse) for this
repository. Reports go to GitHub Support and reach the maintainers without
being public.

If a report contains security-sensitive detail, use
[private vulnerability reporting](https://github.com/genm/rackio/security/advisories/new)
instead, as described in [`SECURITY.md`](SECURITY.md). Do not open a public
issue containing another person's private information — that is itself a
violation of this document.

Reports are handled privately. A reporter is never required to argue their case
in public.

## Enforcement

Maintainers may edit, hide, lock or delete content, and may block accounts, for
conduct they judge to breach this document. Where the conduct is a first
occurrence and appears unintentional, the normal response is a private note
explaining the problem. Repeated or deliberate breaches lead to a block without
further warning.

Because this project currently has a single maintainer, there is no internal
appeal route. A decision you believe is wrong can be escalated to GitHub
Support through the same abuse form.
